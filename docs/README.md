Product and engineering documentation, read in order.

| # | Doc | What it covers |

| 06 | Roadmap | Milestones for Phase 1 (planned) |
| 07 | Go to market | Launch plan, first 100 users, pricing (planned) |

`archive/` holds earlier directions that were considered and set aside, kept for context.

## Conventions

- One doc per concern, numbered in reading order.
- Every doc has a status line (Draft, In review, Approved) and an owner.
- Decisions are recorded where they're made, with the reason. A rejected option is kept, with why.
- Keep it readable: short sections, tables for comparisons, and no filler.
